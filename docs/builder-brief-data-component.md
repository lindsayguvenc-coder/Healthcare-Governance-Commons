# Builder brief: the data component

Moved here from the "Field Activity · coming soon" boxes on the old static node pages (Oct 27, 2026). This is the spec for whoever builds the data component; on the site, node pages now show basic counts in "Evidence at a glance" and grow into this.

## Intended architecture (as written on the node pages)

community-submitted governance engagements, not admin-pushed. Aggregate data feeds per-node stats and a topology map of epistemic status dimensions across the full governance architecture — showing where institutions cluster, where gaps concentrate, how the Unknown / Contested / Unknowable landscape distributes across the field, and the shape of the holes: where gaps are Misplaced, Structural, or False across the full map. Pull-based contribution system with moderation queue. Data schema and contribution system are open builder territory.

## What each node page planned to show

Nodes not listed shared the default: organizations that have hit this node, most common gap flags, maturity distribution, most downloaded outputs, emerging signals.

- **accountability**: organizations that have hit this node · most common accountability shapes identified (misplaced / structural hole / false) · maturity distribution · most downloaded outputs · emerging signals
- **contestation**: organizations that have hit this node · prerequisite gap most commonly missing (documentation / pathway / remedy) · most common contestation scope definitions · remedy types in active use · feedback loop closure rate
- **equity**: organizations that have hit this node · most common equity gaps identified · dominant bias type by use case · subgroup dimensions most frequently absent from monitoring · escalation rate from equity findings
- **explainability**: organizations that have hit this node · most common explainability level gap (mechanism / decision / context) · XAI methods in use by use case · override support adequacy findings · institutions that have specified explainability standards pre-deployment
- **forming**: concepts promoted from this node to full nodes · organizations engaging with forming territory · cluster areas with most field activity · emerging node candidates
- **learning-loop**: organizations that have hit this node · learning category most commonly absent (signal / decision / architecture) · after-action review cadence in active use · architecture review frequency · institutions that have updated governance architecture based on learning loop findings
- **vendor-risk**: organizations that have hit this node · dominant vendor risk category identified (capability / incentive / dependency) · governance rights most commonly absent from contracts · vendor capability assessment findings · dependency risk scores by deployment age

## Also needed (from Lindsay's notes)

- Filtering for AI-generated content and content farms, so a frequency-based view isn't corrupted.
- Pull from sources rather than push, so the map reflects frequency across sources.
